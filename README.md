# mycomfy

EC2 上で ComfyUI を必要なときだけ起動して使うための、自前運用一式。
使い終わったらインスタンスを終了する。モデルは AMI や EBS に持たず、起動時に S3 から取得する。

## 運用原則

- **使うたびに起動**：PoC 中は Spot を先に試し、起動が0台だった場合はオンデマンドで起動を試す。使い終わったらインスタンスを終了する。
- **自前 AMI は持たない**：ベースは AWS 公式の Deep Learning AMI。環境は cloud-init と S3 上のバンドルで再現する。
- **モデルは起動時取得**：モデル類は S3 に置き、起動時にインスタンスストアへ同期する。AMI／EBS に焼かない（保持費を払わない）。
- **調整済みに乗る**：モデルのマージやチューニングは自分でやらない。配布されている調整済みチェックポイントと公開レシピを使う。
- **エラー通知は notify-me 経由**：起動時などの失敗は SNS へ publish し、別リポジトリの notify-me（SNS → SQS → Lambda → LINE）で受け取る。

## ディレクトリ構成

| パス | 中身 |
|---|---|
| `infra/terraform/` | EC2 の起動テンプレート／S3／IAM などインフラの定義 |
| `bin/` | 運用時に使うコマンド |
| `boot/cloud-init/` | 初回起動時の user-data とセットアップ前の準備 |
| `boot/systemd/` | ComfyUI の起動と稼働中の管理 |
| `boot/scripts/` | 初回セットアップから呼ぶスクリプト |
| `bundle/` | ComfyUI＋カスタムノード＋venv を版固定で固めたバンドルの作成手順とスクリプト |
| `models/` | モデル取得マニフェスト（実ファイルは置かない。S3 側に置く） |
| `workflows/api/` | 実行用ワークフロー（API 形式 JSON） |
| `workflows/ui/` | 編集用ワークフロー（UI 形式 JSON） |
| `tools/comfy-tools/` | 補助 CLI（マニフェスト検証、バンドル作成補助など。uv ワークスペース） |
| `ui/` | 簡易 UI（プロンプト文だけを入力する薄い Web UI。後段で実装） |

ルートには全体の入口ファイルだけを置き、実装は各ディレクトリの中に置く。

## 通知コマンド

EC2 では `/usr/local/bin/notify.sh` を `notify.sh "メッセージ" [level]` の形式で呼び出せる。SNS トピックの ARN は環境変数 `NOTIFY_TOPIC_ARN` に設定する。`level` は `error`、`warn`、`info` のいずれかで、省略時は `error`。
